# Contributing to MedSecure ROI Calculator

First off, thank you for considering contributing to MedSecure ROI Calculator! 🎉

Healthcare cybersecurity is critical, and your contributions help hospitals worldwide make informed security investment decisions.

## 🌟 Ways to Contribute

### 1. 🐛 Report Bugs

Found a bug? Please open an issue with:
- Clear description of the problem
- Steps to reproduce
- Expected vs actual behavior
- Browser/OS information
- Screenshots if applicable

### 2. 💡 Suggest Features

Have an idea? We'd love to hear it! Open an issue with:
- Feature description
- Use case / problem it solves
- Proposed implementation (if you have ideas)

### 3. 📊 Update Statistics

Healthcare cybersecurity data changes rapidly. Help us keep it current:
- Update ransomware payment averages
- Add new documented case studies
- Update incident statistics
- Cite sources (preferably verifiable reports)

### 4. 🌍 Add Translations

Help make this tool accessible worldwide:
- Create translated versions of documentation
- Translate calculator interface
- Adapt examples to local contexts

### 5. 📝 Improve Documentation

- Fix typos or unclear explanations
- Add examples or use cases
- Improve installation/usage instructions
- Create video tutorials

### 6. 💻 Code Contributions

- Enhance UI/UX
- Add new features
- Optimize performance
- Improve accessibility

## 🚀 Getting Started

### Prerequisites

- Git installed
- A modern web browser
- Text editor or IDE

### Fork and Clone

```bash
# Fork the repo on GitHub, then:
git clone https://github.com/YOUR_USERNAME/medsecure-roi-calculator.git
cd medsecure-roi-calculator
```

### Make Changes

```bash
# Create a branch
git checkout -b feature/your-feature-name

# Make your changes
# Test thoroughly in multiple browsers

# Commit your changes
git add .
git commit -m "Add: Brief description of your changes"
```

### Submit Pull Request

```bash
# Push to your fork
git push origin feature/your-feature-name

# Go to GitHub and create a Pull Request
```

## 📋 Pull Request Guidelines

### Before Submitting

- [ ] Test your changes in multiple browsers (Chrome, Firefox, Safari)
- [ ] Ensure no console errors
- [ ] Verify calculations are mathematically correct
- [ ] Check responsive design (mobile, tablet, desktop)
- [ ] Update documentation if needed
- [ ] Add comments for complex logic

### PR Description Should Include

- **What** changes were made
- **Why** the changes were necessary
- **How** to test the changes
- Screenshots (for UI changes)
- References to related issues

### Code Style

- Use meaningful variable and function names
- Add comments for complex calculations
- Keep functions small and focused
- Use consistent indentation (2 spaces)
- Follow existing code patterns

## 🔢 Data Accuracy Standards

When updating statistics or case studies:

1. **Always cite sources**
   - Preferably official reports (SEC filings, research papers)
   - Include date of data
   - Include URL or reference

2. **Verify accuracy**
   - Cross-reference with multiple sources when possible
   - Note if data is estimated vs confirmed

3. **Document methodology**
   - Explain calculation methods
   - Note assumptions made

## 🌍 Translation Guidelines

When adding translations:

1. **File naming**: Use ISO language codes (e.g., `README.es.md`, `README.pt-BR.md`)
2. **Completeness**: Translate all user-facing text
3. **Cultural adaptation**: Adapt examples to local context
4. **Maintenance**: Commit to keeping translation updated

## 🎨 Design Guidelines

- Maintain professional appearance
- Ensure accessibility (WCAG 2.1 Level AA)
- Use color contrast checker
- Test with screen readers
- Support keyboard navigation

## 🧪 Testing

Manual testing checklist:

- [ ] Calculator produces correct results
- [ ] All buttons/links work
- [ ] Responsive design works
- [ ] Print layout is readable
- [ ] No JavaScript errors in console
- [ ] Works in Chrome, Firefox, Safari, Edge
- [ ] Works on mobile devices

## 📝 Commit Message Format

Use conventional commits:

```
<type>: <description>

[optional body]
[optional footer]
```

**Types:**
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes
- `style`: Code style changes (formatting)
- `refactor`: Code refactoring
- `test`: Adding tests
- `chore`: Maintenance tasks

**Examples:**
```
feat: Add Portuguese translation
fix: Correct ROI calculation for edge case
docs: Update installation instructions
```
